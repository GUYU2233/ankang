## 3. 识别精度实测（模型评测）

### 3.1 姿态模型专项微调（Pilot 语料，CPU 实跑 30 epoch，约 58 分钟）

数据：362 帧 Pilot 语料（躺卧 242 / 过渡 80 / 站立 40；train 314 / val 48，按源视频组级划分防泄漏）；基础模型 YOLO26s-pose；训练参数见 `runs/pose_ft/pilot_prelabel/args.yaml`（epochs 30、batch 4、imgsz 640、freeze 10、lr0 1e-3、cos_lr、rect）。

结果（`runs/pose_ft/pilot_prelabel/results.csv`，epoch 30 终值）：

| 指标 | 数值 |
|---|---|
| Box（人体框）mAP50 | **0.8527** |
| Box mAP50-95 | 0.5984 |
| Box Precision / Recall | 0.8865 / 0.7797 |
| Pose（关键点）mAP50 | 0.2853 |

## 4. 系统级连续运行实测（端到端稳定性）

### 4.1 运行条件

- 2 路模拟设备（客厅 SIM-LIVING-001、卫生间 SIM-BATH-002），视频源分别循环播放 `data/videos/livingroom/fall/livingroom_fall_001_20260827.mp4`（跌倒样本）与 `livingroom/normal/livingroom_adl_001_20260827.mp4`（正常样本）；
- AI 引擎真实姿态模型推理（YOLO26s-pose，几何+前置风险头路径）；
- 运行窗口：2026-08-28 15:13:11 → 2026-08-31 03:05:49（两段连续运行，合计约 60 小时）；检测周期 2 s/设备，risk_scores 每帧（score≥0.2 或跌倒）落库。

### 4.2 数据库实测统计（backend/zhihu_ankang.db 只读查询）

| 表 | 行数 | 关键统计 |
|---|---|---|
| alert_events | **2318** | RED 440 / ORANGE 180 / YELLOW 1698；fall_event 440 / fall_risk 180 / behavior_risk 1698；status: pending 2317 + closed 1 |
| fall_events | **440** | 设备1（客厅跌倒视频源）226 / 设备2（卫生间）214；fall_prob 0.6–0.8；note=pose_fall（真实姿态检出） |
| risk_scores | **18643** | min 0.20 / max 0.90 / avg **0.5515**；GREEN 84 / YELLOW 13746 / ORANGE 1281 / RED 3532 |
| notification_logs | **2318** | 全部 channel=websocket、status=sent，与告警一一对应 |
| devices | 2 | 均 online（sim） |
| residents | 1 | 测试老人 78 岁（绑定设备1） |
| multimodal_config | 1 | enabled=0（本次运行未启用多模态巡检） |
| monitoring_snapshots | 0 | 与 enabled=0 一致 |
| alert_feedbacks / webhook_configs | 表不存在于该库 | 该库创建早于这两张表上线；新库由 create_all 自动包含（见局限声明） |

**关键验证点**：

1. **真实推理占比**：抽样检查告警 detail_json，`mock=false` 告警 2315/2318（99.9%）——告警由真实姿态模型对数据集视频推理产生，非模拟随机流；仅 3 条为引擎不可用窗口的兜底产物；
2. **告警负荷**：约 60 小时内 2318 条告警 ≈ 39 条/小时（双设备；其中红色 440 ≈ 7.3 条/h），这是在"跌倒视频持续循环回放"这一极端输入下的上限负荷；正常老人活动场景下频次将显著更低，且误报型黄告警由人工核验闭环收敛；
3. **推送成功率**：notification_logs 与 alert_events 完全一致（2318/2318），WebSocket 推送零丢失；
4. **进程稳定性**：两段运行中无服务崩溃记录，进程于 08-31 手动停止（日志无异常退出）；
5. **risk_scores 覆盖**：评分均值 0.55、四档均有分布，风险档案/趋势数据完整可用于看板演示。

> 局限声明（如实）：① 本组数据由"跌倒/正常视频循环回放"驱动，代表**压力与链路稳定性验证**，不代表真实家庭分布的误报率（真实误报率应以 3.3 节单模型口径 + 抑制机制折算并做现场统计）；② fall_events 在本窗口内均未写 end_at（跌倒视频循环导致持续检出或进程停止前未走完恢复帧），恢复机制已由单测（test_fall_event_lifecycle）覆盖；③ 该库不含新表 alert_feedbacks/webhook_configs（建库早于表上线），新部署库自动包含。

## 8. 结论与遗留问题

**结论**：

- 后端 27 例 + AI 引擎 12 例自动化测试实跑通过，覆盖告警状态机、证据融合、风险规则、多模态解析、前置风险头、录制编码、训练不变量等核心逻辑；
- 识别精度：帧级准确率 77.79%、macro-F1 77.39%；**事件召回 90.48%**、延迟 P95 4.33 s，满足实时预警要求；
- 系统级约 60 小时连续运行（2318 告警 / 440 跌倒事件 / 18643 风险分）验证了"视频驱动 → 真实推理 → 分级告警 → 推送落库 → 档案趋势"全链路稳定可运行；
- 功能闭环（模拟 → 红色告警 → 录像回放 → 人工核验 → 处置归档）全程可现场演示。

**遗留问题与改进计划**：

| 遗留 | 影响 | 计划 |
|---|---|---|
| 无萤石/海康真机联调 | 云设备链路仅框架验证 | 申请赛题真机/账号后联调（`/devices/sync` 与 live 取流） |
| tcn_fall.onnx 未入库（gitignore） | 2 例单测与在线时序分支需训练产物 | 随交付包附训练导出产物与导出命令 |
| Pose Pilot 预标注质量偏低（mAP50 0.285） | 躺卧骨架精度受限 | CVAT 人工修正 → 全量复训 → 复测 |
| 误报 7.06 次/h（单模型口径） | 需现场分布统计验证 | 三重抑制已上线；计划真机场景采集后按场景统计 |
| 卧室/卫生间真实样本稀缺 | 场景泛化 | 公开数据集补充 + 模拟器扩展 + 试点采集（合规流程） |
| 本地库不含新增两表 | 旧库升级需重建或迁移 | 新部署自动建表；旧库提供重建脚本（tools/init_db.py） |

## 9. 复现指引（本报告数据怎么再跑出来）

1. 自动化测试：见 §2 命令（backend 27 passed / ai-engine 12 passed + 2 需产物）；
2. 事件级/帧级指标：`ai-engine/models/tcn_fall.metadata.json`（读取即得）；重新生成需先训练：`python -m training.train --model tcn --epochs 60 --device auto` 后 `training.threshold_scan`（命令与口径见《验证设计说明》）；
3. 连续运行数据：按《部署与运行说明》§2 启动三服务，保持模拟设备视频源，运行 ≥24 h 后只读查询 `backend/zhihu_ankang.db`；
4. 姿态微调：`scripts/sample_pose_ft_frames.py` → `prelabel_*.py` → `coco_to_yolo_pose.py` → `finetune_pose.py`（30 epoch CPU 约 1 h）→ `eval_pose_ft_kpi.py`；
5. 前端：`cd frontend && npm run build`。
