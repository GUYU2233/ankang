# 第一部分 部署与运行说明

## 1. 环境要求与依赖

| 运行方式 | 要求 |
|---|---|
| 本地开发（推荐评审复现） | Python 3.11+（代码兼容 3.11/3.13，Docker 镜像用 3.11-slim）、Node.js 20+（仅前端开发需要）、无摄像头要求 |
| Docker 部署 | Docker 24+ 与 Docker Compose v2；GPU 可选（ai-engine 声明 `gpus: all`，无 GPU 自动 CPU 推理） |
| 关键能力 | 无摄像头、无萤石账号、无 GPU 时均可运行——系统自动使用 2 路模拟设备（本地数据集视频循环 + 合成画面）并逐级降级推理 |

Python 依赖（三份 requirements，均在仓库内）：

- `backend/requirements.txt`：fastapi、uvicorn[standard]、sqlalchemy 2、pydantic-settings、httpx、apscheduler、loguru、python-multipart、websockets、numpy、opencv-python-headless、pymysql、cryptography、PyJWT。
- `ai-engine/requirements.txt`：fastapi、uvicorn、numpy、opencv-headless、pydantic、imageio-ffmpeg、ultralytics≥8.2、onnxruntime-gpu≥1.20（onnxruntime 在无 GPU 机器上会自动回退 CPU EP；也可手动换 `onnxruntime`）。
- `ai-engine/requirements-training.txt`（仅训练/复训需要）：torch≥2.0、onnx、onnxruntime、matplotlib 等。

> 磁盘说明：数据集视频经 Git LFS 管理，拉取后需 `git lfs pull`（详见 2.1）；模型 `yolo26s-pose.pt`（约 24 MB）随仓库 LFS 提供。

## 2. 快速复现路线（无 Docker）

### 2.0 准备：获取代码与数据

```powershell
git clone https://github.com/GUYU2233/ankang.git
cd ankang
git lfs install
git lfs pull          # 实体化 data/videos/** 与模型文件
```

**预期结果**：`data/videos/` 下 mp4 均恢复为大文件（非 130 字节 LFS 指针文本）；`ai-engine/models/yolo26s-pose.pt` 存在且约 24 MB。

### 2.1 启动后端（backend，端口 8000）

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

**预期结果**：

- 控制台出现 `智护安康智能预警系统 启动中`、`检测巡检循环已启动`、`多模态巡检循环已启动 enabled=False interval=60s`；
- 首次启动自动执行：建 SQLite（`backend/zhihu_ankang.db`，WAL 模式）→ 写入 1 位测试老人与 **2 路模拟设备**（`客厅-模拟相机01 / SIM-LIVING-001`、`卫生间-模拟相机02 / SIM-BATH-002`，access_url 指向 `data/videos/livingroom/fall/livingroom_fall_001_20260827.mp4` 与 `data/videos/livingroom/normal/livingroom_adl_001_20260827.mp4` 循环播放）；
- 浏览器打开 **http://127.0.0.1:8000/docs** 可见 Swagger 文档；访问 `GET http://127.0.0.1:8000/api/v1/health` 返回 `{"status":"up","auth_mode":"disabled",...}`；
- 控制台每约 2 秒出现一轮设备推理日志；告警触发时出现 `告警触发: 客厅跌倒风险关注提醒 level=...`。

### 2.2 启动 AI 推理引擎（ai-engine，端口 8100）

```powershell
cd ai-engine
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8100
```

**预期结果**：

- 控制台出现 `姿态模型已加载: .../models/yolo26s-pose.pt`（若模型缺失则自动进入兜底，不影响启动）；
- http://127.0.0.1:8100/docs 可用；
- `GET http://127.0.0.1:8100/health` 返回模型加载状态（pose_loaded、temporal_loaded=false 时表示未放置训练产物 tcn_fall.onnx，属预期）、活跃流列表与模型元数据。

> 没有 tcn_fall.onnx 时时序分支不启用：RealRuntime 以几何启发式 + 前置风险头工作（fall_prob 由几何法给出），仍可完整演示；按《验证设计说明》训练导出后放置到 `ai-engine/models/tcn_fall.onnx` 即启用时序判定（`FALL_THRESHOLD=0.95`）。

### 2.3 启动前端（frontend，端口 5173）—— 需要演示 Web 界面时

```powershell
cd frontend
npm install
npm run dev
```

**预期结果**：

- 浏览器打开 **http://127.0.0.1:5173** 自动跳转 `/dashboard`；
- 页面显示"设备总数 2 / 在线 2"与最近告警表；Vite 已将 `/api`、`/ws` 代理到后端 8000；
- 无任何配置即可看到模拟设备视频回放推理结果；出现红/橙/黄告警时页面弹出通知并播放提示音（可设置），看板近 7 天风险趋势随之更新；
- 点击左侧各菜单可验证：设备接入（含"同步萤石云设备"按钮，未配置账号时提示空）、老人档案（含风险因子雷达图）、告警中心（筛选/详情/确认/处置/去核实）、实时画面（MJPEG + 骨架叠加 + 元数据）、视觉巡检（配置/立即检测/巡检历史）、告警录像核实（需要先产生一条 red 告警再点"去核实"）。

### 2.4 复现"红色跌倒告警 → 录像 → 人工核验"全闭环（推荐演示步骤）

1. 三服务按 2.1–2.3 启动后，保持设备 1（客厅）正在循环播放 `livingroom_fall_001_20260827.mp4`；
2. 打开实时画面页 `/live`：预期画面中人物带绿色骨架叠加框；跌倒片段播放时叠加框变红、元数据显示 fall_detected=true / level=red；
3. 打开 `/alerts` 或看板：预期 1–2 分钟内出现红色"客厅检测到疑似跌倒"告警（连续帧确认 + 冷却抑制刷屏，同一事件 30 s 窗口聚合为一条）；
4. 点击该告警"去核实"进入 `/replay/{alertId}`：预期显示录像生成进度（0–100%，由 ai-engine 录制告警前 5 s + 后 5 s 的 MP4）并支持 0.5–2× 倍速回放；
5. 观看完毕后点击"确认跌倒"（或"否认"）：提交 `POST /api/v1/alerts/{id}/verify`，人工权重 1.0 生效；确认后告警状态 → confirmed →（可选 handled/closed），关闭后事件归档；
6. 在老人档案抽屉查看该老人风险档案与趋势（risk_scores 持续落库）。

**预期日志佐证**：backend 控制台出现 `告警触发: ... 疑似跌倒 level=red score=0.9`；ai-engine 出现流状态（actual_fps≈15）；`data/snapshots/pose/YYYYMMDD/` 出现告警证据帧 jpg（fall 告警时）。

## 3. Docker 一键部署（生产形态）


## 4. 萤石开放平台真机联调（赛题平台要求）

1. 注册认证萤石开放平台（open.ys7.com），创建应用获取 appKey/appSecret；
2. 配置 `backend/.env`：

   ```
   EZVIZ_APP_KEY=你的appKey
   EZVIZ_APP_SECRET=你的appSecret
   ```

3. 重启后端，调用 `POST /api/v1/devices/sync` 或前端"设备接入 → 同步萤石云设备"；
   **预期结果**：返回 `{"added": n}`，设备列表出现账号下的萤石设备（serial 去重）；
4. 对设备调用 `GET /api/v1/devices/{id}/live` 获取取流地址（ezopen/hls），`GET /api/v1/devices/{id}/live?protocol=rtsp` 可用时走 RTSP；接入后自动进入巡检与告警链路。

> 未配置账号时对应按钮/接口返回空列表而非报错，演示不受影响。海康设备无真机方案：登记 `vendor=hikvision` + `access_url=rtsp://user:pwd@host:554/Streaming/Channels/101` 即走 RTSP 取流；HCNetSDK 桥接地址 `HIKVISION_NET_SDK_BRIDGE` 预留。

## 6. 常见问题排查

| 现象 | 检查与处理 |
|---|---|
| 前端提示"后端服务离线" | 8000 是否启动；Vite 代理配置（frontend/vite.config.js，可用 BACKEND_PORT 覆盖） |
| 页面无骨架叠加 | ai-engine 未启动或模型缺失——确认 8100 在线（后端自动降级但仍建议启动引擎） |
| 收不到 WebSocket 告警 | 确认 nginx/Vite `/ws` 代理携带 Upgrade/Connection 头；浏览器控制台无 WS 错误 |
| SQLite 并发报错 | 本地单进程无碍；多进程请切 MySQL |
| 视频源打开失败 | 检查路径与 LFS：`git lfs pull`；路径支持仓库相对/绝对/仅文件名（自动在 data/videos 递归查找） |
| 告警过密/过稀 | 调整 ALERT_CONFIRM_FRAMES、冷却（AlertEngine 15 s）与聚合窗口（30 s） |
| Docker ai-engine 无法用 GPU | 无 GPU 环境移除 `gpus: all` 并安装 CPU 版 onnxruntime |

## 8. 数据库设计（字段级要点）

- `residents`：name(索引)/gender/age/address/medical_history/guardian_name/guardian_phone/created_at。
- `devices`：device_name/device_serial(唯一索引)/vendor(sim|ezviz|hikvision|onvif|rtsp)/scene(客厅|卧室|卫生间)/status/model/access_url(RTSP 或本地路径)/channel_no/enabled/resident_id(FK)。
- `alert_events`：alert_no(唯一)/device_id/resident_id/level(SAEnum green|yellow|orange|red)/event_type(fall_event|fall_risk|behavior_risk)/title/detail_json(JSON：score、fall_prob、nearfall_prob、gait_unsteadiness、fall_type、factors、events、trigger_reason、mock、occurrence_count、max_score、max_fall_prob、snapshot_path、replay_clip_id)/status(pending|confirmed|handled|closed 状态机，String(16)+索引)/confirmed_by|at|note、handled_*、closed_at/created_at(索引)。
- `alert_feedbacks`：alert_id/device_id/source(human|vision_ai|detector)/target(fall|risk)/decision/confidence/weight/operator/note/snapshot_path/metadata_json。
- `fall_events`：device_id/resident_id/alert_id/start_at/end_at(未空=活动)/fall_prob/screenshot_path/note(fall_type)。
- `risk_scores`：resident_id/device_id/score/level/factors_json/created_at。
- `notification_logs`：alert_id/channel(websocket|sms|voice|app)/target/content/status。
- `multimodal_config`：单行 id=1；provider/model/base_url/api_key(加密)/enabled/interval_seconds/temperature/max_tokens/prompt_override。
- `webhook_configs`：name/platform(wechat|dingtalk|feishu|custom)/webhook_url/secret(加密)/enabled/trigger_levels(默认 red,orange)。
- `monitoring_snapshots`：device_id/resident_id/provider/model/event_type/severity/confidence/has_issue/level/summary/detail_json(含 raw 原文)/snapshot_path/alert_id/latency_ms/created_at。

迁移策略：本地 SQLite 启动时 `_migrate_sqlite()` 幂等补列并回填状态机；生产 MySQL 由 SQLAlchemy `create_all` 建表（`deploy/init.sql` 仅建库）。

## 10. 核心算法实现（技术要点）

### 10.1 在线推理（RealRuntime，`ai-engine/app/pipelines/real_runtime.py`）

1. **姿态**：YOLO26s-pose（conf 0.35，`torch.cuda.is_available()` 自动选设备）；过滤（有效关键点 ≥4）→ 去重（IoU>0.85 保留关键点多者）；
2. **跟踪**：bbox IoU≥0.20 贪心匹配维持 track_id；时序缓冲键 `{stream}:t{track_id}` 按轨迹隔离，轨迹消失即清理；主目标选择：跌倒者优先 > 上帧锚点 IoU 连续（≥0.15）> 最大面积；主目标跌倒引发身份跳变（锚点 IoU<0.15）时清空时序窗防混人；
3. **归一化**：以髋中点为原点、肩髋距离为尺度（COCO 17 点，conf<0.3 置零），输入 `(1,3,32,17)`；
4. **时序融合**：TCN（0.65）+ ST-GCN（0.35）双 ONNX 加权 logits → softmax → `map_temporal_probs`（2 类：fall=probs[1]；3/4 类按序拆分）；窗口未满返回 None（暖机期以几何因子兜底但不触发跌倒）；`FALL_THRESHOLD=0.95`；
5. **几何兜底/交叉验证** `_fall_by_keypoints`：髋高比<0.18 或（踝-髋距<0.6×躯干）→fall_prob 0.8；否则 lean 映射 `(lean-0.8)*2`，>0.55 判跌；他人几何判跌兜底（fall_prob 提到 0.8）覆盖"主目标未跌、他人跌"的多人场景；
6. **前置风险头**（prefall_head.py，16 帧缓冲）：nearfall 由 hip_drop_recover / squat / sit_fast / stagger 取最大，已倒地帧抑制 ×0.15、上限 0.85；gait 由 lean_std(0.45) + ankle 轨迹(0.30) + torso jitter(0.25) 合成（无步态时 0.65/0.35）；
7. **输出**：person_count/fall_detected/fall_prob/nearfall_prob/gait_unsteadiness/fall_type/risk_factors(5 项 kinematic)/risk_score/level/keypoints/bbox/tracks/mock=false。

### 10.2 后端风险引擎（risk_scoring.py + risk_engine.py）

- 因子规格见《专项研究报告》§6.3；kinematic 取自 ai-engine risk_factors 白名单抽取；behavioral 由 `BehavioralTracker` 按 `r{resident}:d{device}` 键跨帧累积（静止计时/卫生间计时/夜间计数/步态 std）；
- 评分 = 加权平均，与 `fall_prob×0.95` 取大；规则升档与 `build_trigger_reason`（最多 4 段，如"步态不稳(0.82) + 卫生间停留超时"）生成可读原因随 detail_json 下发；
- RiskEngine 保留 12 帧滑动窗口接口（兼容旧调用）。

### 10.3 预警引擎（alert_engine.py）

- 每帧处理：score ≥0.20 或跌倒 → 写 risk_scores；红/橙/黄连续帧计数；达到 `confirm_frames` 且距上次发射 ≥15 s → 发告警并复位计数；
- 30 s 聚合窗口内同设备同类型不重复建单（occurrence_count 累加、max_score/max_fall_prob 更新、可升级红色）；
- 写 NotificationLog + 异步 webhook（钉钉 HMAC-SHA256 签名/飞书卡片/企业微信 markdown，按 trigger_levels 过滤，日志不泄露 URL）；
- fall 时维护每设备活动 FallEvent（首次建、之后只抬高 fall_prob），连续 3 帧非跌倒写 end_at 恢复；
- 证据帧 `data/snapshots/pose/%Y%m%d/dev{id}_{uuid}.jpg`（imencode 写盘兼容非 ASCII 路径，失败仅告警不阻断）。

### 10.4 多模态巡检（multimodal_*）

- 提示词固定 schema 11 字段；`level_for(event_type,severity)`：critical→red/high→orange/medium→yellow；`should_alert` 按事件最低严重度（fall≥medium、posture_abnormal/other_risk≥high、floor_clutter≥medium、normal 永不）；
- 解析兼容 fenced JSON/噪声；数值越界夹取回退；
- 截图 `runtime/multimodal/` 留存；结果写 monitoring_snapshots（latency_ms、raw 原文）；命中即 AlertEvent（source=multimodal）+ NotificationLog + （fall）FallEvent；
- 7 家预设提供商密钥分别取 `*_API_KEY` 环境变量；DB 中 api_key 以 AES-256-GCM 加密（AAD="multimodal.api_key"；webhook secret 用 "webhook.secret"）。

### 10.5 人机核验与证据融合（alerts.py / feedback.py）

- 权重：human=1.0、vision_ai=0.35、detector=0.65；融合 `fused = Σw·d/Σw`，阈值 0.60；
- `verify`（人工）：decision 与 event_type target 一致性校验；误报（decision=false）自动 handled + 关闭活动 FallEvent + 写 feedback(human)；
- `ai-verify`：调多模态大模型看图回执（低权重），只出 fused_score/decision 不回写状态；
- 反馈导出策略：human 且带证据帧才可进入离线训练候选（training_allowed=false 保护），杜绝 AI 自证闭环。

### 10.6 取流与模拟（stream_service.py / sim_provider.py）

- 统一入口 `get_frame(device)`：rtsp → OpenCV VideoCapture（全局锁串行化，规避 FFmpeg 多线程断言）；本地视频（mp4/avi/mkv）→ 循环播放（结尾回卷 0 帧）；其余 → SimCamera 状态机合成帧（1280×720，walking→unsteady→falling→fallen→walking，随设备 id 播种）或返回兜底元数据；
- `draw_overlay` 在帧上画 17 点骨架 + bbox + 等级配色（后端本地兜底路径）；ai-engine 侧流式路径则由引擎返回已标注 JPEG，避免重复编码；
- 后端无 AI 引擎时 `build_demo_result` 提供 demo 结果保证告警链路可演示（mock 标记贯穿）。

### 10.7 AI 引擎流式架构（streaming.py）

- `StreamManager` 每流一个后台线程：OpenCV 解码 → 按目标节拍（默认 15 FPS，文件源不跳帧保证时序连续）推理 → 画标注 → JPEG(85) → 单槽最新帧 + 环形回放缓冲（5 s 预录）；
- `trigger_recording(alert_id, post_seconds=5)`：冻结预录 + 续录 → 异步 ffmpeg（imageio-ffmpeg 自带二进制）编码 H.264 MP4（yuv420p/faststart，偶数尺寸处理）→ `runtime/recordings/{clip_id}.mp4` + 同名 json manifest；
- 后端每 2 s 只读 `latest` 聚合结果，避免高频 HTTP/JPEG/DB 压力（连接池 httpx max 32、keepalive 16）。

### 10.8 训练与评测管线（ai-engine/training/）

- 入口：`python -m training.train --model tcn|stgcn|prefall [--classes binary|ternary|multiclass] [--epochs 60] [--device auto]`；
- 流程：manifest + source_mapping → 受试者键标注 → 80/20 分层划分（seed 42，防泄漏）→ YOLOv8-Pose 抽骨架缓存（`data/annotations/skeleton/*.npz`）→ 滑窗建集（window 32/stride 16/15 FPS）→ 训练（TCN hidden 128/layers 6/kernel 3/dropout 0.3；class_weight）→ best macro_f1 存 `.pt` → 写 `.metrics.json/.confusion.png/.audit.json` → 导出 ONNX（opset 17，输入 skeleton (N,3,T,17)）；
- 阈值扫描 `threshold_scan.py`：事件级召回/误报每小时/延迟扫描选优，产出 threshold_sweep.json 与 event_metrics.json（场景细分）；
- `training/README.md` 记载口径与局限（550→590 manifest 演化）。

## 12. 安全与合规设计

- 接口鉴权：业务 API 全部要求 `X-API-Key`（HMAC 常量时间比对），health/metrics/WS 公开；生产 compose 强制 `AUTH_MODE=required` 与 `API_KEY`、`SECRET_ENCRYPTION_KEY`（`:?` 必填校验）；
- 密钥存储：AI/渠道密钥 AES-256-GCM 静态加密 + 独立 AAD；日志脱敏（webhook 只记 host、api_key 打码 head4/tail4）；
- 证据路径校验：告警证据帧/巡检快照接口仅允许各自目录内文件；
- 数据合规：数据集仅公开许可来源、不采集真实老人影像；系统定位为安全提醒工具、不构成医疗诊断（界面与提示词均含免责声明）；
- 前后端隔离：前端只依赖 /api/v1 与 /ws，无直接数据库访问。
