> 用途：回应赛题"作品须基于萤石开放平台进行开发或能力调用"的要求，汇总仓库内萤石开放平台（open.ys7.com）能力调用的**代码实现证据**与**运行联调现状**。

## 2. 代码级证据 A：OpenAPI 调用实现（核心）

文件：`backend/app/core/ezviz_adapter.py`（123 行，注册名 `ezviz`，随初始骨架提交，历史见 git `5b5a6fa`）

### A1. 接口调用总表（与萤石开放平台官方 OpenAPI 对应）

| # | 萤石 OpenAPI | 本系统函数 | 请求参数 | 返回解析 | 行号 |
|---|---|---|---|---|---|
| 1 | `POST /api/lapp/token/get` | `EzvizAdapter.ensure_token()` | appKey、appSecret | accessToken + expireTime；**提前 60 s 自动续期**，进程内缓存 | L39–51 |
| 2 | `POST /api/lapp/device/list` | `EzvizAdapter.list_devices()` | accessToken、pageStart、pageSize=50（**分页循环**） | deviceName/deviceSerial/status/channelNo → 统一设备字典 | L53–83 |
| 3 | `POST /api/lapp/device/status/get` | `EzvizAdapter.get_device_status()` | accessToken、deviceSerial | status==1 → online/offline；异常降级 offline | L85–97 |
| 4 | `POST /api/lapp/live/address/get` | `EzvizAdapter.get_live_address()` | accessToken、deviceSerial、channelNo、protocol（1=rtmp/hls，2=ezopen） | url + type → `StreamAddress(protocol=ezopen\|hls)` | L99–109 |
| 5 | `POST /api/lapp/device/capture` | `EzvizAdapter.get_snapshot()` | accessToken、deviceSerial、channelNo、quality=1 | picUrl → HTTP GET 下载图片字节 | L111–123 |

### A2. 协议实现要点（可审查）

- **请求方式**：`httpx.post(f"{settings.ezviz_api_base}{path}", data=form, timeout=15)`，`ezviz_api_base=https://open.ys7.com`（`backend/app/config.py` L24）；即官方要求的 HTTPS POST + application/x-www-form-urlencoded；
- **返回码约定**：`code in ("0","200")` 视为成功，否则抛 `RuntimeError("萤石开放平台接口异常: {path} code=... msg=...")`——与官方文档"code=0/200 表示成功"一致（L35–36）；
- **Token 生命周期**：`expireTime` 秒级过期控制，**剩余 60 s 内强制刷新**（L40），适配器实例内缓存，避免每次调用重复换 token；
- **异常隔离**：设备状态查询失败只记 warning 并返回 offline（L95–97），不影响检测主链路；同步失败由 `DeviceManager` 捕获并 `logger.warning`（`device_manager.py` L54–55）。

### A3. 适配器抽象与注册

- `backend/app/core/device_adapter.py`：`DeviceAdapter(ABC)` 定义 `list_devices()/get_device_status()/get_live_address()/get_snapshot()/start_alarm_subscription()`；`DeviceAdapterFactory.register("ezviz", EzvizAdapter)` 类装饰器注册（`ezviz_adapter.py` L12）；
- 告警订阅能力：抽象类预留 `start_alarm_subscription()` 兜底实现（返回 None），真机联调时对接萤石消息推送服务（见 docs/04 §3"告警订阅"）。

## 3. 代码级证据 B：调用触发链路（系统内真实可触发）

| 触发点 | 代码位置 | 行为 |
|---|---|---|
| **后端启动自动同步** | `backend/app/main.py` L22–25（lifespan：`ensure_demo_devices` → `sync_cloud_devices`） | 服务启动即调用 `DeviceManager.sync_cloud_devices`，对有凭据的 ezviz/hikvision 适配器执行设备发现 |
| **REST 手动同步** | `POST /api/v1/devices/sync`（`backend/app/api/devices.py` L77–81） | `mgr.sync_cloud_devices(db)` 返回 `{"added": n}` |
| **前端按钮** | `frontend/src/views/Devices.vue` L8「同步萤石云设备」→ L136 `onSync()` → `api.syncDevices()` | 家属/护工端一键同步萤石账号下设备 |
| **设备入库去重** | `device_manager.py` L36–58 | 按 `device_serial` 查重，新设备写 `devices` 表（vendor=ezviz、status、model、channel_no、extra_json 存原始返回） |
| **状态巡检刷新** | `device_manager.py` L75–88 `update_status()` | 对 vendor=ezviz 设备调 `status/get` 刷新在线状态 |
| **取流地址下发** | `GET /api/v1/devices/{id}/live`（`devices.py` L84–94） | ezviz 设备返回 `{protocol: ezopen|hls, url}` 供前端播放与 AI 消费 |
| **登记入口** | `POST /api/v1/devices`（`devices.py` L35–44） | 支持 vendor=ezviz 手工登记（device_serial 唯一，重复 409） |
| **前端 vendor 选项** | `Devices.vue` L44 `<el-option label="萤石云" value="ezviz" />` | 登记表单可选"萤石云"设备类型 |

> 语义说明：萤石同步在"无配置/无设备"时返回 0、不报错（`list_devices` 对未配置返回 `[]`，`device_manager` L31），因此开发/演示环境启动不受影响——这正是赛题"无真机也能演示、配置凭据即联调"的分层设计。

## 7. 真实调用复现步骤（评审/联调用，约 3 分钟）

```powershell
# 1) 在 open.ys7.com 注册开发者账号并创建应用（获取 appKey/appSecret，赛题支持可申请）
# 2) 配置凭据（不入库）
cd backend
@"
EZVIZ_APP_KEY=你的appKey
EZVIZ_APP_SECRET=你的appSecret
"@ | Out-File -Encoding utf8 .env

# 3) 启动后端（启动日志应出现"萤石开放平台 accessToken 已刷新"或同步结果日志）
python run.py

# 4) 手动同步（幂等，可重复执行）
curl -X POST http://127.0.0.1:8000/api/v1/devices/sync
#    预期: {"added": n}    （n = 账号下新设备数；再次执行应返回 0，序列号去重生效）

# 5) 校验入库与状态
curl http://127.0.0.1:8000/api/v1/devices
#    预期: 列表中出现 vendor="ezviz" 的设备

# 6) 取直播地址
curl http://127.0.0.1:8000/api/v1/devices/{ezviz设备id}/live
#    预期: {"protocol":"ezopen"|"hls","url":"..."}

# 7)（可选）抓拍：调用适配器 get_snapshot 验证 device/capture
```

**调用留痕（供证据存档）**：联调时后端日志（loguru）会记录 `萤石开放平台 accessToken 已刷新`、`告警触发` 等；如需结构化留痕可开启日志落盘，或对 `/api/lapp/*` 的请求/响应做一次 tcpdump/httpx 日志抓取保存为附件。
