# 验证设计说明

> 作品：智护安康——老年人跌倒风险识别与智能预警系统（XH-202617 跌倒风险方向）
> 本文件说明作品的**验证目标、验证口径、验证方法、评测指标定义、数据与代码的复现路径**，以及验证的边界与局限，作为《实测数据与功能测试报告》（docs/09-）的方法学配套，回应赛题评审中"技术有效性与性能合理性、验证方案科学严谨"的要求。

---

## 1. 验证目标与总体原则

### 1.1 验证目标

1. 证明系统**可实现**：跌倒前预判—跌倒时预警—跌倒后快速响应的全流程功能真实存在、可操作；
2. 证明系统**可运行**：本地与 Docker 两种形态均可一键启动，无真机/无 GPU 也能闭环演示；
3. 证明系统**可验证**：识别精度、时延、误报等关键指标有明确定义、有实测数据、可复现，且与提交文档一致（一致性要求）。

### 1.2 总体原则（贯穿全部验证）

- **分层验证**：代码级（单元/不变量测试）→ 组件级（模型离线评测）→ 系统级（端到端连续运行）→ 业务级（功能闭环演示）；
- **数据分层报告**：数据集按 **场景 × 受试者 × 来源** 分层统计指标，防止把"某场景好"误推广为"全部场景好"；
- **防泄漏**：任何训练/验证划分以受试者键为最小单位（URFD 双机位同事件归同一键、Le2i 按源文件独立），杜绝同受试者跨集；
- **口径透明**：帧级指标与事件级指标分开报告，单模型口径与在线抑制口径分开报告，如实标注模拟/真实、兜底/正式推理的标记（mock 字段贯穿全链路）；
- **可审计**：全部关键指标落在仓库内可读取的产物上（metadata.json / results.csv / 数据库 / 测试报告），不依赖口头声明。

## 2. 评测指标定义（与实现一一对应）

### 2.1 帧级指标（时序模型验证集）

在按受试者划分的验证集（68 段，帧滑窗样本）上：

| 指标 | 定义 | 实现位置 |
|---|---|---|
| 准确率 Accuracy | (TP+TN)/(P+N)，帧窗口级二分类（fall / non_fall） | `ai-engine/training/metrics.py` |
| macro-F1 | 各类 F1 的算术平均（二分类即两类均值） | 同上 |
| 混淆矩阵 | 预测 × 实际 2×2/4×4 矩阵 | 训练输出 `*.confusion.png` |

### 2.2 事件级指标（评测核心，贴近业务）

以"视频片段"为事件单元：

| 指标 | 定义 | 计算（threshold_scan.py） |
|---|---|---|
| 事件召回率 Event Recall | 跌倒视频中，跌倒事件时间窗内至少一次判定超阈的比例（窗口贴帧 → 概率超阈即命中） | `training/threshold_scan.py`：对 fall 视频贴真实跌倒区间 |
| 误报率 False Alarms/h | 非跌倒视频中，超阈事件折算为每小时次数（合并间隔 merge_gap=1 s，相邻超阈帧并为一次事件） | 同上，对 nonfall 视频统计 |
| 检测延迟 Delay | 首次超阈帧时间 − 跌倒起始标注时间（秒）；报告 median 与 P95 | 同上 |

阈值选择：对 thr ∈ [0.20, 0.95] 步长 0.05 扫描，以 `score = recall − 0.15×(FAR/60)` 权衡选优，过程与结果落盘 `runs/threshold_sweep.json`、`runs/event_metrics.json`；现网采用 **FALL_THRESHOLD=0.95**（高门槛优先压误报，配合在线多重抑制）。

### 2.3 系统级指标

| 指标 | 定义 | 观测方式 |
|---|---|---|
| 端到端稳定性 | 连续运行期无崩溃/无推送丢失 | 数据库全表核对 + 进程存活记录 |
| 推送成功率 | notification_logs / alert_events 条数比 | SQL 核对 |
| 告警负荷 | 告警条数/小时（按等级） | DB 时间聚合 |
| 功能通过率 | 自动化用例 passed/total | pytest |

## 4. 复现路径（评审可按步执行）

### 4.1 环境（约 10 分钟）

```powershell
git clone https://github.com/GUYU2233/ankang.git && cd ankang
git lfs install && git lfs pull
# 后端
cd backend; python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# AI 引擎（如要完整时序链路，另行训练导出 tcn_fall.onnx 放入 models/；无则自动几何兜底）
cd ..\ai-engine; python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 4.2 代码级复现

```powershell
cd backend; python -m pytest tests -q        # 期望 27 passed
cd ..\ai-engine; python -m pytest tests -q   # 期望 12 passed + 2 需产物
```

### 4.3 模型级复现（约 1–2 小时，CPU 可跑；GPU 更快）

```powershell
cd ai-engine
pip install -r requirements-training.txt
# 1) TCN 训练（540→590 manifest 均可；产物含 .metrics.json/.confusion.png）
python -m training.train --model tcn --epochs 60 --device auto --skip-skeleton  # 已有骨架缓存时可跳过抽骨架
# 2) 事件级评测（产出 threshold_sweep.json / event_metrics.json）
python -m training.threshold_scan --checkpoint ai-engine/runs/tcn_binary_w32.pt --device auto
# 3) 导出在线模型
python -m training.export_onnx --checkpoint ai-engine/runs/tcn_binary_w32.pt --out ai-engine/models/tcn_fall.onnx
# 4) 姿态微调复现（Pilot 30 epoch CPU ≈ 1 h）
python scripts/finetune_pose.py --data data/annotations/pose_ft/pose_ft.yaml --epochs 30 --device cpu
python scripts/eval_pose_ft_kpi.py --model ai-engine/runs/pose_ft/<最新>/weights/best.pt
```

**一致性校验点**：重新训练导出的 metadata.json 中 accuracy/macro_f1 应与提交的 77.79%/77.39%（同划分、同 seed 42 时）一致或在合理波动内；任何复现差异应记录。

## 5. 验证边界与局限（如实声明）

1. **真机边界**：萤石/海康设备接入为框架级验证（适配器 + 模拟流），尚未真机联调；赛题平台能力调用以 OpenAPI 集成代码 + 文档为准，计划申请真机后补联调记录；
2. **数据边界**：数据为公开许可数据集重组（无真实老人跌倒影像，主体为年轻受试者模拟与公开演示），识别指标的外推能力受此限制；按 README 建议以"场景/受试者/来源"分层解读，避免跨分布过度推广；
3. **样本边界**：卧室 6 段、室外 1 段、卫生间 2 段的事件级样本量小（召回 100% 不代表零风险），扩充后需复评；夜间片段 53 段占 9%，夜间专项评测待补；
4. **模型产物边界**：tcn_fall.onnx / stgcn onnx 为训练导出物（按工程约定不入 git），随交付介质附产物与导出命令，保证 2 例单测与在线时序分支可复现；
5. **Pilot 姿态语料边界**：预标注质量待人工修正（Pose mAP50 0.285），Box 检出 0.853 已可用；全量复训后以 eval_pose_ft_kpi 复测（outdoor+低清躺卧关键点检出 ≥8、站立帧不退化 ≥15 点）；
6. **误报率边界**：7.06 次/h 为单模型无抑制口径，真实场景误报须按三重抑制 + 人工核验闭环后的"用户可见告警"口径现场统计；
7. **环境差异**：CPU 推理时延与 GPU 有差异（影响帧率与延迟下限），性能结论以同环境复测为准。
