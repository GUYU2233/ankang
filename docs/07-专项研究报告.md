## 1. 摘要

跌倒是我国老年人居家养老场景中发生率高、致残率高的核心安全威胁。针对现有跌倒防护手段"以事后检测与响应为主、缺乏跌倒发生前的风险预判、误报疲劳、设备厂商与场景覆盖受限"等问题，本作品面向 XH-202617 赛题跌倒风险方向，构建了**"跌倒前预判—跌倒时预警—跌倒后快速响应"全流程闭环**的老年人跌倒风险识别与智能预警系统"智护安康"。

系统基于萤石开放平台能力开发，预留海康威视设备兼容接入层，无真机时支持 RTSP/本地视频/合成流模拟，形成"设备接入 → 取流抽帧（15 FPS）→ 姿态骨架估计 → 时序跌倒检测 + 前置风险头 + 多模态大模型巡检 → 滑动窗口风险评分 → 绿/黄/橙/红四级预警 → WebSocket 实时推送 → 家属/护工确认处置 → 事件归档与趋势看板"的完整链路。

核心研究贡献包括：

1. **关口前移（前置预判）**：在传统"跌倒后识别"之外，设计独立前置风险头 `HeuristicPoseRiskHead`，从 16 帧短时姿态缓冲实时估计**近跌概率（nearfall_prob）**与**步态不稳度（gait_unsteadiness）**，叠加"长时间静止、卫生间停留超时、夜间频繁离床"等行为因子，实现跌倒发生前的黄/橙预警；
2. **双引擎感知**：骨架时序模型（YOLO26s-pose + TCN 时序卷积，32 帧 × 15 FPS 滑窗）负责"人的动作"识别，多模态大模型（Qwen-VL / GLM-4V / GPT-4o / Gemini 等，OpenAI 兼容协议）负责"环境与上下文风险"（地面杂物、烟火、漏水等）定时巡检，二者互补；
3. **分级预警与误报抑制**：四级（绿/黄/橙/红）分级预警 + 连续多帧确认 + 告警冷却 + 滑动窗口平滑三重机制；告警处置采用 4 态状态机并引入"人工（权重 1.0）/视觉 AI（0.35）/检测器（0.65）"三级证据融合的人机核验闭环；
4. **多厂商适配**：萤石 OpenAPI、海康 HCNetSDK/ISAPI/RTSP、通用 ONVIF/RTSP、本地视频/合成模拟流四类设备统一适配，可利旧接入存量摄像头。

实测结果（可复现）：自建多源数据集 590 段（跌倒 318 / 近跌 73 / 正常 154 / 风险行为 45，约 120.2 分钟）；TCN 时序模型按受试者划分验证，帧级准确率 77.79%、macro-F1 77.39%；事件级评测（63 段跌倒视频）**跌倒事件召回率 90.48%**，误报 7.06 次/小时，检测延迟中位 0.27 s、P95 4.33 s；客厅/卧室/室外场景事件召回分别为 89.3% / 100% / 100%。系统后端 27 例单元测试与 AI 引擎 12 例测试全部按仓库现状实跑验证（2 例依赖训练产物的用例除外），并完成约 60 小时连续自动巡检实测（累积 2318 条告警、440 条跌倒事件、18643 条风险评分）。

## 2. 题目背景与意义

### 2.1 深度老龄化与跌倒威胁

习近平总书记指出，"满足老年人多方面需求，让老年人能有一个幸福美满的晚年，是各级党委和政府的重要责任"。当前我国 60 岁及以上人口已超 3 亿，进入中度老龄化社会。在居家养老场景中，跌倒、心理健康问题与诈骗风险构成三大核心安全威胁，其中**跌倒**具有高发生率与高致残率：

- 我国每年约有 **4000 万**老年人经历跌倒事件；
- 60 岁及以上老年人跌倒后骨折比例达 **36.84%**；
- 近 **4 成**跌倒事件发生在家庭环境中；
- 传统"事后响应"模式难以及时干预——老人跌倒后长时间无人发现（"长躺"）会显著增加致死致残风险。

### 2.2 研究意义：从"跌倒后识别"走向"跌倒风险前置防控"

尽管现有技术在跌倒行为识别方面已具备一定精度（如萤石识别准确率可达 80% 以上），但整体仍以"事后检测与响应"为主，存在三方面不足：

1. **缺乏前置预判**：步态不稳、踉跄、快速坐下等"差点摔倒"的前兆信号无法被捕获，预警不能前置到跌倒发生之前；
2. **误报疲劳**：单帧规则判据误报多，家属/护工对告警逐渐脱敏；
3. **设备与场景受限**：摄像头品牌繁杂、协议不统一；夜间、卫生间等高危场景覆盖薄弱。

本作品的意义在于：围绕赛题要求，面向跌倒风险方向实现从"跌倒后识别"到"**以跌倒风险前置防控为核心，融合跌倒前预判、跌倒时预警、跌倒后快速响应**"的全流程技术升级，输出一套可运行、可演示、可复现、可落地的智能预警系统，为居家养老场景的安全保障提供技术支撑与工程样例。

### 4.1 总目标

面向 XH-202617 赛题跌倒风险方向，构建**"跌倒前预判—跌倒时预警—跌倒后快速响应"**全流程闭环的老年人跌倒风险识别与智能预警系统，实现在居家养老典型场景（客厅、卧室、卫生间等）下对跌倒潜在风险的精准研判、分级预警与处置闭环，并通过实测数据支撑方案的可实现性、可运行性与可验证性。

### 4.2 技术路线


## 6. 核心技术与创新实现

### 6.1 骨架 + 时序跌倒检测（跌倒时识别）

- **骨架提取**：ultralytics YOLO26s-pose（默认 `models/yolo26s-pose.pt`，支持 `POSE_MODEL_PATH` 覆盖），逐帧输出 COCO 17 关键点；工程处理含低质量检测过滤（有效关键点 ≥4）、IoU>0.85 去重、跨帧 bbox IoU≥0.20 贪心轨迹跟踪，主目标选择优先级"跌倒者 > 锚点连续 > 最大面积"，保证多人场景时序输入不混人；
- **时序建模**：TCN 时序卷积网络（`training/models.py`，窗口 32 帧 ≈2.1 s、步长 16、输入 `(1,3,32,17)` 归一化骨架、输出 fall/non_fall logits），ONNX Runtime 部署；另预留 ST-GCN 融合位（TCN 0.65 / ST-GCN 0.35 加权融合，模型就位即启用）；
- **判据融合与高门槛**：跌倒软概率取时序 softmax 的 fall 类（或窗口未满/模型缺失时的几何启发式），`FALL_THRESHOLD` 默认 **0.95** 高门槛压误报；几何判据（髋部高度比 <0.18 或踝-髋距 <0.6 倍躯干等）作为兜底与交叉验证；**窗口未满（暖机期）不触发跌倒**；
- **模拟降级链**：姿态模型不可用 → 几何启发式仍不可用 → `MockRuntime` 合成兜底（mock=True 标记），保证无 GPU/无模型环境系统闭环不中断。

### 6.2 前置风险头：跌倒前预判（核心创新）

- 独立模块 `ai-engine/app/pipelines/prefall_head.py`，按 stream_id 维护 16 帧短时姿态缓冲，输出两类 0–1 信号：
  - **nearfall_prob（近跌概率）**：捕捉"未完成跌倒"的姿势线索——髋部骤降后回升（hip drop & recover）、快速下蹲（squat）、快速坐下（sit fast）、站立踉跄（stagger）；已经倒地的帧会抑制近跌（×0.15），避免与跌倒检测语义冲突，且**近跌永不置位 fall_detected**；
  - **gait_unsteadiness（步态不稳度）**：由躯干倾斜摆动幅度、踝部轨迹散乱度、躯干抖动三项合成（系数 0.45/0.30/0.25），对应帕金森步态、共济失调等高危步态特征；
- 与 2 类现网 TCN 兼容：`map_temporal_probs` 支持 2/3/4 类 softmax 拆分（4 类标签 fall/nearfall/risk_behavior/normal 训练入口已就绪，`--classes multiclass --model prefall`）；
- 训练侧预留 `training.models.PrefallRiskHead` 与 `--model prefall`，当前启发式实现可在未来被 4 类时序头 ONNX 无缝替换（接口不变）。

### 6.3 风险因子评分与场景化规则（前置决策）

`backend/app/core/risk_scoring.py` 维护 8 个归一化风险因子（值 0–1，越大越危险）：

| 类别 | 因子（key） | 权重 | 说明 |
|---|---|---|---|
| kinematic（逐帧） | nearfall_prob 跌倒前兆 | 0.18 | 快速下蹲/踉跄/沉髋回升等 |
| kinematic | posture_height 姿态高度异常 | 0.14 | 髋部离地高度过低 |
| kinematic | body_lean 躯干倾斜 | 0.12 | 肩髋中心横向偏移/躯干长 |
| kinematic | support_base 支撑面不稳 | 0.08 | 双踝间距相对躯干过窄 |
| behavioral（跨帧） | inactivity 长时间静止 | 0.14 | 默认 >120 min 计满 |
| behavioral | gait_unsteadiness 步态不稳 | 0.16 | 后端窗口 std + AI 步态分取大 |
| behavioral | bathroom_dwell 卫生间停留 | 0.10 | 默认 >30 min 计满 |
| behavioral | night_trips 夜间频繁离床 | 0.08 | 夜间 22–6 点离床 ≥3 次计满 |

评分：`score = max(Σw·v/Σw, fall_prob×0.95)`；跌倒直接抬至 ≥0.90 并输出可读 `trigger_reason`（如"步态不稳(0.82) + 卫生间停留超时"）；规则升档：卫生间超时 ≥0.70（橙）、久坐/久卧/夜间离床/步态不稳 ≥0.45（黄）、近跌 ≥0.70 升橙 / ≥0.45 升黄（**近跌升黄橙但不抬红**，避免把"差点摔"误报成"已摔"）。级别映射：跌倒或 ≥0.85→红；≥0.70→橙；≥0.45→黄；否则绿。

### 6.4 分级预警、误报抑制与处置闭环

- **四级告警**：绿（正常）/黄（行为风险提示）/橙（跌倒高风险）/红（跌倒告警），颜色语义贯穿看板、推送消息、实时画面叠加框与证据帧；
- **三重误报抑制**：连续 ≥2 帧（`alert_confirm_frames`）确认才告警 + 单设备告警冷却 15 s + 同设备同类型 30 s 窗口聚合（occurrence_count 累计、max_score/max_fall_prob 跟踪，可升级为红）；
- **事件生命周期**：每设备唯一活动 `fall_events`，连续 3 帧非跌倒判定"恢复"写 end_at；告警 4 态状态机 pending→confirmed→handled→closed（附处置人/时间/备注，非法跳转 409）；
- **人机核验（证据融合）**：人工现场核验权重 1.0（一票定音），视觉 AI 二次确认权重 0.35，检测器 0.65，融合阈值 0.60；确认误报自动置 handled 并关闭对应跌倒事件；AI-only 反馈永不进入训练候选池（`training_allowed=false`），人工核验通过后才会导出离线训练样本——形成"AI 只做候选、人工审核"的安全数据闭环；
- **录像回放核实**：告警触发即向 ai-engine 请求录制（告警前 5 s 环形缓冲 + 告警后 5 s），MP4 落盘并提供倍速回放页，供家属/护工核对后决定确认/否认——从"报个警"升级为"可核实的证据闭环"。

### 6.5 多模态大模型视觉巡检（双引擎之一）

- 独立巡检循环：每 60 s（可配）对每路摄像头取帧截图，调多模态大模型识别（7 家 OpenAI 兼容预设：通义 qwen3-vl-plus / 智谱 glm-5v-turbo / OpenAI gpt-5.6-sol / Gemini / 豆包 / DeepSeek / 自定义，密钥加密存储）；
- 五类结构化事件：`fall`（跌倒/倒地）、`posture_abnormal`（姿态/行为异常）、`floor_clutter`（地面杂物/障碍）、`other_risk`（火灾烟雾/漏水等）、`normal`；输出含 severity/confidence/summary/details/location_hint/suggestion，严格 JSON schema 解析（兼容代码围栏与噪声文本）；
- 结果落库 `monitoring_snapshots`（含截图证据与原始文本），命中告警策略即进入同一套四级告警 + WebSocket 推送（`source=multimodal`），跌倒事件同步写 `fall_events`；
- 与骨架链路的定位差异：**骨架时序管"人的实时动作"，多模态大模型管"环境与上下文风险"**——地面杂物这类绊倒隐患只能由视觉大模型提前发现。

### 6.6 多厂商设备适配

- `DeviceAdapter` 抽象 + 工厂注册：**萤石**（OpenAPI：token/get、device/list、status/get、live/address/get、device/capture，token 提前 60 s 自动续期）、**海康**（HCNetSDK 桥接预留 + ISAPI + RTSP 规范 `rtsp://user:pwd@host:port/Streaming/Channels/{ch}{0|1}01`）、**ONVIF/RTSP**（通用兜底）、**模拟**（SimCamera 状态机 walking/idle/unsteady/falling/fallen 或本地视频循环）；
- 无真机/无云账号时系统自动使用 2 路内置模拟设备 + 数据集视频循环回放，保证全链路真实可演示。

|---|---|---|---|---|---|
| livingroom 客厅 | 283 | 56 | 129 | 44 | 512 |
| bedroom 卧室 | 24 | 17 | 24 | 1 | 66 |
| outdoor 室外 | 10 | — | — | — | 10 |
| bathroom 卫生间 | 1 | — | 1 | — | 2 |
| **合计** | **318** | **73** | **154** | **45** | **590** |

环境构成：夜间片段 53 段、≥720P 片段 212 段；多视角、多遮挡、多光照条件（详见 `data/meta/environment.csv`、`data/README.md`）。

### 7.2 来源与许可（合规声明）

- 主体来自公开学术数据集：URFD（100 段，CC BY-NC-SA）、Le2i（130 段，CC BY-NC-SA，Charfi 2013）、CAUCAFall（100 段，CC BY 4.0）、GMDCSA-24（160 段，CC BY 4.0），补充 WebVideo/公开演示片段与 SmartHome-Bench 壁挂真实家居片段，另有团队自采户外实拍 10 段；
- **合规三原则**：仅使用公开许可数据 / 不采集真实老人影像（无真实老人跌倒样本，均为年轻受试者模拟或公开演示）/ 时间戳与标注不杜撰（源自官方标注或帧分析工具，逐一记录 `note` 字段）；
- 全部视频均附同名事件标注 JSON（`data/annotations/action_events/`，590 份）、230 份官方帧级 bbox（`frame_bbox/`）、551 份 15 FPS 骨架缓存（`skeleton/*.npz`）、200 份配套 IMU 加速度/同步 CSV（`meta/sensor/`，源自 GMDCSA 官方 IMU 数据）。

### 7.3 划分策略（防泄漏）

按**受试者键**分层划分（默认 80/20、seed 42）：URFD 双机位同事件（cam0/cam1）归并同一键（`urfd:fall-01`），Le2i 按源文件独立成键，杜绝同一受试者跨训练/验证集泄漏；`risk_behavior` 在二分类中归入 non_fall，在四分类中独立成类。

## 8. 实验与结果

### 8.1 姿态模型专项微调（Pilot）

针对通用姿态模型对**躺卧/跌倒姿态**漏检关键点的问题，团队搭建了 CVAT 标注 → YOLO-pose 微调数据管线（`scripts/` 六个脚本：采样/预标注/格式转换/微调/KPI 评估），生成 362 帧 Pilot 语料（躺卧 242 / 过渡 80 / 站立 40，train 314 / val 48，严格按源视频组级划分防泄漏），对 YOLO26s-pose 微调 30 epoch（CPU，实测 58.5 分钟）：

| 指标 | 数值（epoch 30） | 来源 |
|---|---|---|
| Box mAP50 | **0.8527** | runs/pose_ft/pilot_prelabel/results.csv |
| Box mAP50-95 | 0.5984 | 同上 |
| Pose mAP50 | 0.2853（Pilot 预标注语料，提示需人工修正后复训） | 同上 |

> 说明：Pilot 阶段 Pose 指标偏低源于预标注质量，已列入"人工修正后全量复训"计划；Box 检出（跌倒者定位）已达可用水平，也是骨架时序链路的主要受益项。

### 8.2 TCN 时序模型评测（离线）

现网 2 类 TCN（`tcn_fall.metadata.json`，540 条清单 / 472 训练 / 68 验证，按受试者划分）：

| 指标 | 数值 |
|---|---|
| 帧级准确率 | **77.79%** |
| 帧级 macro-F1 | **77.39%** |
| 事件级：跌倒视频数 / 召回 | 63 段 / **90.48%**（事件窗口内超阈即命中） |
| 事件级：非跌倒视频 | 46 段，误报 **7.06 次/小时** |
| 检测延迟 | 中位 **0.27 s** / P95 **4.33 s** |

场景细分（同元数据文件）：客厅 56 段跌倒检出 50（召回 89.3%，35 段非跌倒仅 1 次误报）；卧室 6/6（100%，11 段非跌倒 0 误报）；室外 1/1（100%，0 误报）。

> 口径说明：帧级与事件级差异主要来自"滑窗贴标签 + 事件窗口命中"两种评估粒度；正式提交按**场景 × 受试者 × 来源**分层报告（见《验证设计说明》）。

### 8.3 端到端连续运行实测（系统级）

该实测验证了"视频回放驱动 → 真实姿态推理 → 分级告警 → 推送落库"全链路的**长时间稳定性**与**事件闭环**，红色告警 detail 中的 fall_type=pose_fall、mock=false 表明由真实姿态模型产出。

## 9. 核心创新点

1. **关口前移（跌倒前预判）**：独立前置风险头量化"近跌概率"与"步态不稳度"，叠加卫生间停留、夜间离床等场景化行为因子，在真正跌倒前发出黄/橙预警——与现有"跌倒后报警"方案有本质区别；
2. **全流程闭环**：跌倒前—中—后一体化，四级预警 + 三重误报抑制 + 4 态处置状态机 + 人机核验证据融合 + 录像回放核实 + 风险趋势档案，从"一次性报警"升级为"可核实的持续风险管理"；
3. **双引擎感知**：骨架时序模型盯"人的动作"，多模态大模型盯"环境与上下文风险"，互相补盲区（如地面杂物隐患只有视觉大模型能发现）；
4. **多厂商兼容**：萤石 OpenAPI + 海康桥接/ISAPI/RTSP + ONVIF/RTSP + 本地/模拟四类统一适配，养老机构与家庭存量摄像头可直接利旧；
5. **场景化阈值与误报治理**：不同场景差异化因子与规则升档（卫生间→橙、久坐/夜间离床/步态→黄），配合连续帧确认/冷却/聚合，卧室场景实测 0 误报。

## 11. 总结与展望

**总结**：本项目建成"设备接入—双引擎 AI 感知—四级预警—处置闭环"的完整跌倒风险预警系统，590 段数据集、跌倒事件召回 90.48%、P95 检测延迟 4.33 s、约 60 小时连续运行实测与 27+12 例自动化测试均证明其**可实现、可运行、可验证**。

**局限**（如实声明）：
- 尚无萤石/海康真机联调，设备链路以框架 + 模拟/RTSP 验证为主；
- 公开数据以年轻受试者模拟跌倒为主，无真实老人跌倒样本，浴室真实样本稀缺；
- 现网为 2 类 TCN + 启发式前置头，4 类时序头与 ST-GCN 融合的正式训练待人工修正语料后开展。

**展望**：真实场景试点与真机联调；IMU/毫米波雷达等多传感器融合；姿态微调全量复训与 4 类时序头替换启发式；面向赛题心理健康、反诈识别方向的能力延伸。
